## Findings

### H3-RT-001 — Vercel preview fails
**Severity:** P1 / hard H3 blocker  
**Evidence:** GitHub commit status for `b0c7afdae65ece5b853f80128d3f94a15b6d8b3e` is `failure` from Vercel. The failing integration targets project `nexova-premium-v0-challenger`, i.e. the historical challenger project rather than a clean production preview target.  
**Effect:** H3 requires a reachable Vercel preview for the exact candidate.  
**Disposition:** requires Vercel project/configuration repair or re-link. This cannot be marked PASS from local CI.

### H3-RT-002 — No-JS evidence is missing and the HTML has no fallback
**Severity:** P1  
**Evidence:** the workflow invokes `no-js-390.png`, but the uploaded artifact contains no such file. `uis/website/index.html` contains only an empty React root plus the module script, so disabling JavaScript provides no meaningful content.  
**Effect:** explicit H3 No-JS readability criterion fails.  
**Repair:** add a concise semantic `noscript` fallback and replace the unreliable screenshot-only probe with an asserted browser audit.

### H3-RT-003 — Horizontal-overflow check is not actually asserted
**Severity:** P1  
**Evidence:** H3 requires an automated browser assertion. Current CI only takes screenshots. Several desktop grids use percentage tracks summing to 100% **plus** a non-zero gap (e.g. 34% + 66% + 4rem), while `body { overflow-x: hidden; }` can mask overflow in screenshots.  
**Effect:** screenshots are insufficient evidence and hidden overflow is plausible.  
**Repair:** convert affected proportional grids to `fr` tracks so gaps are included in available width, then assert `scrollWidth <= clientWidth` at every required viewport.

### H3-RT-004 — Browser-interaction criteria are not asserted
**Severity:** P1 evidence gap  
**Evidence:** current workflow does not assert console errors, keyboard traversal, visible focus or mobile-nav open/close behavior.  
**Repair:** add a dependency-free Chrome DevTools Protocol audit using Node 22 + the existing system Chrome.

### H3-RT-005 — Operating Philosophy does not match the locked Golden
**Severity:** P2 visual fidelity  
**Evidence:** locked Figma H2 uses a code-native organic material field with three clipped ellipses. Runtime substitutes the A2 fibrous image. Exact desktop Golden geometry:
- field 560×560, black;
- bone ellipse: x -70, y 90, 430×520, opacity .72;
- crimson ellipse: x 160, y -90, 410×660, opacity .56;
- ochre ellipse: x 260, y 160, 360×520, opacity .30.

Mobile Golden field is 350×280 with three independently translated ellipses.  
**Repair:** implement the Golden material field in CSS; keep A2 for the transition/closing roles where it is approved.

### H3-RT-006 — Image format opportunity, not a heavy-master violation
**Severity:** P3  
**Evidence:** runtime PNG derivatives are already small:
- A1 desktop 80,441 B
- A1 mobile 144,444 B
- A2 desktop 51,983 B
- A2 mobile 51,386 B

Lighthouse still estimates ~168 KiB savings from modern formats.  
**Disposition:** optimization opportunity, not a blocker for this bounded H3 repair because the heavy masters are not the default network payload.

### H3-RT-007 — Figma copy is English while runtime copy is Spanish
**Severity:** documented implementation variance, not a visual defect  
**Evidence:** the runtime document is explicitly `lang="es"` and the production copy is consistently localized. The section hierarchy and content roles remain equivalent.  
**Disposition:** preserve Spanish product copy; judge H2 fidelity on composition, hierarchy, crop and typography rather than literal English strings.
