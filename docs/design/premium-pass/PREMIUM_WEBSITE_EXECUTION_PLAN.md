# Nexova Premium Website Execution Plan

**Status:** APPROVED  
**Branch:** `design/oni-nocturne-premium-pass`  
**Academic recovery branch:** `baseline/4g-006-academic-pass`

## Objective

Replace the current academically-valid but visually insufficient Nexova website with a production-grade implementation faithful to **Oni Nocturne Oxblood**, while preserving the validated academic baseline and avoiding unnecessary architectural change.

The website is a **Persuade** surface. The future backoffice premium translation is an **Operate** surface and must not inherit the website's cinematic density.

## Authority order

1. 4Geeks rubric and assignment constraints
2. Nexova approved product/company truth (`CONTEXT.md`)
3. Oni Nocturne Oxblood approved visual identity
4. Direction Contract
5. Figma Golden Lock
6. Existing Nexova repository architecture
7. Validated runtime evidence
8. External design Skills / reference systems
9. v0 challenger output

External tools may propose or critique; they do not silently become authority.

## Complexity contract

Every new dependency must answer:

1. What exact problem does it solve?
2. Why are existing/native capabilities insufficient?
3. What complexity does it remove?
4. What failure surface does it introduce?
5. Is the net visual/engineering gain material?

If the answer is weak, defer or remove it.

## Phase 3 — Direction Contract

Create `DIRECTION_CONTRACT.md`.

Initial website settings:
- surface mode: Persuade
- design variance: 8/10
- motion intensity: 7/10
- visual density: 3/10

Preferred:
- asymmetry;
- editorial scale contrast;
- overlapping planes;
- controlled negative space;
- cinematic image mass;
- restrained ornaments.

Reject:
- generic centered SaaS hero;
- default 3-card layout;
- meaningless bento;
- generic glassmorphism;
- AI-purple/neon;
- generic networks/orbs;
- fake social proof;
- tattoo-shop poster treatment;
- gaming UI.

**DoD**
- an independent designer could produce recognizably the same visual family from the contract;
- the identity is distinguishable from generic AI-company design.

## Phase 4 — Asset Bible and production

Create `ASSET_CONTRACT.md`.

Tier A:
- Hero Oni
- Peony mass
- Sumi atmosphere
- Signature background/landscape

Tier B only if composition requires it:
- blood moon
- secondary Oni detail
- ritual ornament

Tier C preferably code-driven:
- grain
- lacquer sheen
- paper/noise
- borders/rules

Generation budget per Tier A role:
- maximum 3 independent initial candidates;
- select 1 winner;
- maximum 1 material repair round.

Every asset records:
purpose, source, ratio, focal point, desktop/mobile crop, safe text zone, resolution, palette, permitted treatment, forbidden treatment, consumers and status.

Reject assets with visible generative slop, unusable crops, generic fantasy-poster composition or inconsistent visual grammar.

**DoD**
- all Tier A roles have approved production candidates;
- mobile and desktop cropping are viable;
- no raster contains generated UI/text;
- rejected assets are not optimized.

## Phase 10 — Motion architecture

Create `MOTION_SPEC.md`.

Three layers:
1. CSS — hover/focus/simple transforms
2. Motion — local reveals, navigation, controlled springs
3. GSAP + ScrollTrigger — explicitly required for one signature sequence

GSAP authority is limited to the signature scroll choreography.

Target budget:
- 1 signature GSAP sequence;
- 2–4 recurring Motion patterns;
- CSS microstates.

All motion must have a reduced-motion path.
