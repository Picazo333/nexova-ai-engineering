# Nexova Project Principles

These are stable engineering/process principles. They do **not** freeze the future Nexova product roadmap.

1. **Cumulative monorepo.** Relevant 4Geeks company milestones evolve this repository rather than creating disconnected Nexova implementations.
2. **Rubric first.** Academic requirements are satisfied and evidenced before optional engineering extensions.
3. **Minimum sufficient architecture.** Pursue maximum technically justifiable quality/complexity, not maximum possible infrastructure.
4. **Deterministic where sufficient.** Rules, policies and constraints remain deterministic when probabilistic/agentic behavior adds no justified value.
5. **Evidence before abstraction.** Implement the Nexova-specific problem first; extract a generic capability only after stable/repeated evidence.
6. **Evidence before productization.** Commercial potential remains a hypothesis until real use/evidence supports it.
7. **Progressive context.** Agents load the smallest safe context and deepen only when the task requires it.
8. **Federated authority.** Nexova owns its product/domain/runtime state; Noema owns protocol/conformance; Control Tower owns 4Geeks governance; Skill Foundry owns Skill lifecycle decisions.
9. **Durable coordination.** Material state, decisions and evidence must be reconstructible from repository artifacts.
10. **Human gates for material decisions.** Architecture, security, autonomy, sensitive-data, destructive changes and productization require explicit human authority when consequences are material.
11. **Quality is independently proven.** Noema conformance, successful code generation or persuasive documentation are not substitutes for tests, runtime evidence or rubric proof.
12. **Historical ideas remain revisitable.** Prior Nexova agent/product concepts are candidate inputs unless promoted by a current evidence-backed decision.
